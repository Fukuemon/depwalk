## 背景・目的

メソッド改修時の影響範囲調査では「どこから呼ばれ・どこを呼んでいるか」を網羅的・再帰的に辿る必要がある。IDE の Call Hierarchy や grep では網羅性・再帰性が欠ける。本 feature は、Analyzer が生成した呼び出しグラフ上で **caller / callee を再帰探索する Traversal Engine** を設計し、調査の自動化の中核を担う。

関連: [design/DesignDoc.md](../../design/DesignDoc.md) Why/What (S1/S2)、Goal (G1/G2)、モジュール責務 (Traversal Engine / Graph Engine)、Future Work Phase1。

## 想定ユーザー/ステークホルダー

- 開発者 / 保守担当: 改修対象メソッドの呼び出し元・呼び出し先を調べたい
- CI パイプライン: プルリク時に影響範囲を自動レポートしたい (バッチ実行)

## 提供価値(成功条件)

| #   | 成功条件                                                         | 測定方法                                              |
| --- | ---------------------------------------------------------------- | ----------------------------------------------------- |
| S1  | 指定メソッドの呼び出し元を再帰的に探索し到達集合を網羅列挙できる | サンプル Java/Spring で既知の caller 集合と出力が一致 |
| S2  | 指定メソッドの呼び出し先を探索し列挙できる                       | 同上 (callee 方向で既知集合と一致)                    |

## スコープ

### やること

- caller 方向の再帰探索 (G1)
- callee 方向の探索 (G2)
- 探索アルゴリズム (BFS / DFS) と探索方向の指定
- Graph Engine が構築したグラフ (Node / Edge) を入力とした探索
- 循環・再帰の検出と探索打ち切り

### やらないこと

- ソースの解析そのもの (→ `analyzer-protocol` / `java-analyzer`)
- 出力整形 (Console/JSON/DOT/Mermaid) (→ `output`)
- Spring DI 解決・Interface Dispatch 解決 (Analyzer 側 / Phase2-3)

## 業務ルール

| #   | ルール                                              | 理由                            | 備考            |
| --- | --------------------------------------------------- | ------------------------------- | --------------- |
| R1  | 探索は Graph Engine 経由でのみグラフへアクセスする  | Core 内の依存方向を単方向に保つ | architecture.md |
| R2  | 訪問済みノードは再訪しない (循環で無限ループしない) | 再帰呼び出し・循環参照への耐性  | Q4 で詳細確定   |
| R3  | 探索方向 (caller/callee) は呼び出し側が明示指定する | 双方向の責務を1エンジンに集約   |                 |

## 入出力要件

### 入力

| #   | 項目         | 必須/任意 | 形式                | 制約/備考                         |

## 例外シナリオ

| #   | シナリオ                   | ユーザーへの見せ方             | 代替手段                      |

## 権限要件

- 非該当 (CLI ツールでありロール / 認可の概念を持たない)。

## 監査/非機能要件

### 監査・運用

- 探索打ち切り (循環/深さ) はログまたは出力標識で観測可能とする。

### 非機能(性能/可用性/セキュリティ/保守)

- 大規模コードベースのグラフでも実用的な時間で探索完了すること (具体目標値は spec で設定)。
- 解析対象は read-only。状態を持たずプロセス内で完結する。
