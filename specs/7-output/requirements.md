## 背景・目的

調査結果の呼び出しグラフは、人が読む用途 (Console) と機械処理・可視化用途 (JSON / DOT / Mermaid) の双方で利用される。CI レポートやドキュメント貼り付けにも使えるよう、複数の出力形式を **Output Engine** に集約して設計する。

関連: [design/DesignDoc.md](../../design/DesignDoc.md) Why/What (S3)、Goal (G3)、モジュール責務 (Output Engine)、Future Work Phase1/Phase4。

## 想定ユーザー/ステークホルダー

- 開発者 / 保守担当: ターミナルで結果をすぐ確認したい (Console)、図にして共有したい (DOT/Mermaid)
- CI パイプライン: 機械可読な形式でレポートを保存・後処理したい (JSON)

## スコープ

### やること

- Phase1: Console / JSON 出力
- Phase4 (I/F は本 feature で設計): DOT / Mermaid 出力
- Traversal 結果 (グラフ/木) を各形式へシリアライズする出力 API
- Console ツリー表現 (深さ表示・循環参照の見せ方)

### やらないこと

- グラフのビューワ提供 (DOT/Mermaid の生成まで。レンダリングは外部ツール) — Non Goals
- 探索ロジック (→ `traversal`)
- 解析・Model 定義 (→ `analyzer-protocol` / `java-analyzer`)

## 業務ルール

| #   | ルール                                                   | 理由                     | 備考            |

## 権限要件

- 非該当 (CLI ツール)。

## 監査/非機能要件

### 監査・運用

- JSON 出力はスキーマバージョンを持ち、後方互換の方針を spec で定める。

### 非機能(性能/可用性/セキュリティ/保守)

- 大規模グラフでも各形式を実用時間で出力できること。
- 出力先は標準出力 / ファイル。外部送信は行わない。
