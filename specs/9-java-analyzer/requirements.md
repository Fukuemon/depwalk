## 背景・目的

Phase1 の対象は Java/Spring Boot。本 feature は `analyzer-protocol` の SPI / JSONL スキーマを **実装する最初の言語別 Analyzer** を設計する。AST 解析・型解決・(段階的に) DI 解決・CallGraph 生成を担い、JavaParser / SymbolSolver / SootUp を用いる。Spring の DI 経由の呼び出し先解決は段階導入する。

関連: [design/DesignDoc.md](../../design/DesignDoc.md) モジュール責務 (Java Analyzer)、Why/What (S4)、Future Work Phase1〜3、Communication Protocol。

## 想定ユーザー/ステークホルダー

- 開発者 / 保守担当: Java/Spring プロジェクトの呼び出し関係を解析させたい
- Core: 本 Analyzer が Protocol 準拠の `MethodSymbol` / `CallEdge` を返すことを期待する

## 提供価値(成功条件)

| #   | 成功条件                                                     | 測定方法                                                   |
| --- | ------------------------------------------------------------ | ---------------------------------------------------------- |
| S4  | Spring DI 経由の呼び出し先を実体まで解決できる (Phase2 以降) | interface 注入を含むサンプルで実装クラスのメソッドが現れる |

> Phase1 は JavaParser ベースの静的呼び出し抽出を成功条件とし、DI/Interface Dispatch 解決は Phase2/Phase3 で段階的に達成する。

## スコープ

### やること

- Java ソースの AST 解析 (JavaParser)
- 型解決 (SymbolSolver)
- CallGraph 生成 → `analyzer-protocol` の JSONL スキーマで出力
- Analyzer SPI 実装 (独立プロセスとして Core から起動される)
- 段階導入: Spring Bean/DI 解決 (Phase2)、Interface Dispatch / Override 解決 (Phase3, SootUp)

### やらないこと

- 共通契約 (SPI / Protocol / Model) の定義 (→ `analyzer-protocol`)
- グラフ探索 (→ `traversal`)、出力整形 (→ `output`)
- Reflection / AspectJ Runtime / 実行時 Proxy の動的解析 (Non Goals)

## 業務ルール

| #   | ルール                                                       | 理由                      | 備考                |
| --- | ------------------------------------------------------------ | ------------------------- | ------------------- |
| R1  | 出力は `analyzer-protocol` の JSONL スキーマに厳密準拠する   | Core 無変更で結合 (S5)    | Q1 は protocol 正本 |
| R2  | 独立プロセスで動き Core の言語ランタイムに依存を持ち込まない | P2 (ランタイム混在の回避) |                     |
| R3  | DI/Dispatch 解決は Phase に沿って段階導入する                | Phase1 を軽く立ち上げる   | Future Work         |

## 権限要件

- 非該当 (CLI ツール)。

## 監査/非機能要件

### 監査・運用

- 未解決シンボル・部分解析の発生を観測可能にする (調査の信頼性のため)。

### 非機能(性能/可用性/セキュリティ/保守)

- 大規模 Java プロジェクトを実用時間で解析できること (目標値は spec)。
- 対象ソースは read-only。外部送信なし。
