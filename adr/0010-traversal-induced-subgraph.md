# ADR-0010: Traversal の結果を誘導部分グラフと SCC の判定で定める

## Status

承認

## Context

- Traversal Engine は、起点のメソッドから caller か callee の方向に呼び出しグラフをたどり、到達 node 集合、到達 edge 集合、`cycle` 注釈、`depthLimit` cutoff を返す。
  - 探索の設計は [Traversal の Design Doc](../core/internal/traversal/DesignDoc.md) が持つ。
- 呼び出しグラフでは、共有のメソッドが複数の箇所から呼ばれる合流の構造がふつうにある。
- 呼び出しは循環しうるので、無限にたどらないための打ち切りが要る。
- request は探索順序（BFS か DFS）を受け取る。

## Decision

結果を、探索の副産物（どの edge をたどったか）ではなく、グラフの性質として定める。

- 到達 node 集合は、起点からの最短の距離 `minDepth` が `maxDepth` 以下の node とする。
- 到達 edge 集合は、両端が到達 node 集合に属する、探索の方向に沿ったすべての edge（誘導部分グラフ）とする。
- `cycle` 注釈は、到達部分グラフの中で閉路をなす edge（self-loop か、同じ SCC の中の edge）に付ける。

こうすると、結果は探索順序にまったく依存せず、決定的になる。  
到達集合の計算には最短の距離の走査が 1 本あれば足り、探索順序は結果にも探索の実行にも影響しない。

## Considered Options

| 選択肢                                                     | 強み                                                                               | 弱み                                                                                                      |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **採用:** 誘導部分グラフと SCC の判定で結果を定める        | 結果が探索順序に依存せず決定的になる。循環していない合流の edge を循環と標識しない | —                                                                                                         |
| 実際にたどった edge だけを結果に含める探索木の edge の方式 | —                                                                                  | BFS と DFS のどちらを選ぶかで、結果に残る edge が変わる。循環していない合流の edge を循環と誤って標識する |

## Consequences

### Positive

- BFS と DFS のどちらを指定しても、到達 node 集合、到達 edge 集合、`cycle` 注釈、`depthLimit` cutoff の内容が同じになる。
- 合流の構造で、同じ node へ向かう複数の edge がすべて到達 edge 集合に含まれる。

### Negative

- 到達 edge 集合は tree ではないので、Console の tree の表現は Output の側で組む必要がある。
