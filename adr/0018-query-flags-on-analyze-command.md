# ADR-0018: 探索のクエリを、サブコマンドを足さずに analyze コマンドの flag で指定する

## Status

承認

## Context

`depwalk analyze` は、解析の対象を `--language`、`--analyzer-cmd`、`--analyzer-meta` の flag で受け取る。  
`--method` を省くと、件数の要約と diagnostics だけを出す。  
起点のメソッドから caller か callee を探索し、深さの上限と出力の形式を指定する手段が要る。

探索のクエリを足す形は、次の 2 つが候補になる。

- `analyze` コマンドに、探索を指定する flag を足す。
- 探索の種別ごとに、新しいサブコマンドを足す。

どちらの形でも、探索の前に Analyzer を起動して graph を作る。  
そのため、解析の対象を指定する flag は、どのクエリでも同じものが要る。

## Decision

探索のクエリは、サブコマンドを足さずに、`analyze` コマンドの flag（`--method`、`--direction`、`--max-depth`、`--format`）で指定する。  
理由は次の 3 つ。

- 解析の対象を指定する flag を、1 つのコマンドにだけ定義すればよい。
- `--method` を省いたときの要約の出力と、既存の flag をそのまま保てる。
- 実装の変更が、既存のコマンドへの flag の追加で済む。

新しい出力の形式は、`--format` の値を足して提供する。  
2 つのメソッドの間のパスの探索のような新しいクエリの種別は、要るようになったときに、サブコマンドを足すか flag を足すかを決める。

## Considered Options

| 選択肢                                               | 強み                                                                                   | 弱み                                                                                               |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **採用:** `analyze` コマンドに探索の flag を足す     | 解析の対象の flag を 1 か所で定義できる。`--method` を省いたときの要約の出力を変えない | クエリの種別が増えると、`analyze` の flag が増える                                                 |
| 探索の種別ごとにサブコマンドを足す（caller、callee） | クエリの種別ごとに help と flag を分けられる                                           | 解析の対象の flag をサブコマンドごとに定義する。`analyze` の要約の出力との関係を決め直す必要がある |

## Consequences

### Positive

- 解析の対象を指定する flag の定義が 1 か所にまとまる。
- `--method` を省いた `analyze` の出力は、探索の flag を足す前と同じになる。

### Negative

- クエリの種別が増えるほど、`analyze` の flag が増え、help が長くなる。
- 新しいクエリの種別を足すときに、サブコマンドにするか flag にするかを改めて決める必要がある。
