# ADR-0008: 可視化の出力（DOT / Mermaid）をスコープから外し、解析の精度と永続化を先に進める

## Status

承認

## Context

depwalk は当初から、出力の形式として Console、JSON、DOT、Mermaid の 4 つを掲げ、ロードマップでも「グラフ出力（DOT / Mermaid）」を独立した段として置いていた。  
DOT と Mermaid は `Format` の定数だけがあって formatter を登録しておらず、`--format dot` は許容値のエラーになっていた。  
Goal、成功条件、スコープ、ロードマップは [Design Doc](../design/DesignDoc.md) が持つ。

Phase 1 の実装を通して、**残っている弱点は出力の形式の数ではない**ことがはっきりした。

- 呼び出しグラフに **edge が 1 本欠けると、答えが間違う**。
  - 影響の調査で最も危険なのは偽陰性である。
  - Java と Spring では、framework 由来の暗黙の edge が取りこぼしの温床になる。
    - 例: アノテーション駆動の呼び出し（`@Scheduled`、`@EventListener`）、Mapper の interface（MyBatis、Spring Data JPA）、lambda と method reference
- **解析が重い**。
  - Gradle daemon の起動と SootUp の索引の構築を毎回行うため、繰り返しクエリを投げる使い方に耐えない。
- **「この PR で影響範囲がどう変わったか」に答えられない**。
  - 結果を request ごとに in-memory で捨てており、2 つの時点を比べられない。
  - 途中の状態を request の中に閉じ、永続的なストアを持たない規約は [codebase.md の State Ownership](../context/codebase.md#state-ownership) にある。

出力の形式を増やしても、これらは 1 つも解けない。

## Decision

### 1. DOT と Mermaid をスコープから外す

Goal、成功条件、スコープから DOT と Mermaid を除き、対応する形式を **Console と JSON の 2 つ**にする。  
出力の形式と formatter の契約は [Output の Design Doc](../core/internal/output/DesignDoc.md) にある。

可視化そのものを永久に否定するのではなく、**形式を決めないまま、ロードマップの後ろへ置く**。  
DOT と Mermaid が最適な形式とは限らないためである。

### 2. 可視化の形式は、再び入れるときに決め直す

DOT は Graphviz、Mermaid は対応するビューアという**外部のレンダラへの依存**を、利用者に負わせる。  
再び入れるなら、自己完結した単一の HTML を出す案（`--format html`）を含めて比べ直す。  
いま形式を決めておく利益はない。

### 3. 提供の形は CLI に限ったままにする

Web Viewer は、現行の Non Goals（「IDE Plugin / Web UI の提供（本ツールは CLI に限定する）」）と正面から衝突する。  
今回は Non Goals を保ち、採用するときは提供の形そのものを別の ADR で決め直す。

### 4. ロードマップの前の方を、次の順に置き換える

1. 解析の精度の強化
   - framework 由来の暗黙の edge を拾い、偽陰性を減らす。
2. グラフの永続化（commit SHA の単位）
   - 再解析を避け、2 つの時点の差分（PR による影響範囲の変化）に答えられるようにする。
   - 途中の状態を request の中に閉じて永続的なストアを持たないという現行の規約を変えるため、着手するときに別の ADR が要る。
3. CI との連携（Artifact、PR のコメント）
   - グラフの永続化の上に乗る。単独では毎回フルの解析になり、実用に耐えない。

## Consequences

### Positive

- Goal と成功条件が、実際に目指すものだけになる。
- 出力の形式を足すより先に、答えの正しさ（解析の精度）と実用の速度（永続化）に資源を向けられる。
- 可視化の形式を、将来の要件に合わせて選び直せる。

### Negative

- 可視化の口が当面なくなる。グラフを図で見たい利用者は、JSON から自分で変換する必要がある。
- `core/internal/output` に `FormatDOT` と `FormatMermaid` の定数が残る。
  - formatter は未登録で `--format dot` は許容値のエラーになるため、**利用者から見た挙動は変わらない**が、コードと文書の対応は崩れる。
  - 定数の削除は、挙動を変えない cleanup として別に扱う。
