# PR コメント投稿と指摘への対応記録

`multi-agent-review` のレポートを GitHub PR へコメントとして投稿する手順と、投稿した指摘に対する対応の記録方法。

## 投稿の前提

- 対象が PR のときだけ使える (diff / spec 対象では投稿先がない)。
- **投稿は公開行為**。投稿前にレポート本文をユーザーに提示し、承認を得てから投稿する。
- 投稿には `gh` CLI と PR への書き込み権限が必要。無ければ標準出力レポートのみで終える (エラーにしない)。

## 投稿手順 (レポート 1 本方式)

統合レポートを **1 本のコメント** として投稿する。指摘ごとに複数コメントをばら撒かない (通知が荒れ、対応状況を追えなくなるため)。

1. レポート本文の先頭に識別マーカーを付ける:

   ```markdown
   <!-- multi-agent-review -->

   ## Multi-agent review (<timestamp>)

   ...
   ```

2. 既存の投稿を探す (再実行時の重複防止):

   ```bash
   gh api repos/{owner}/{repo}/issues/<PR番号>/comments \
     --jq '.[] | select(.body | startswith("<!-- multi-agent-review -->")) | .id'
   ```

3. 既存コメントがあれば **更新**、なければ新規投稿:

   ```bash
   # 更新
   gh api --method PATCH repos/{owner}/{repo}/issues/comments/<comment-id> -F body=@report.md
   # 新規
   gh pr comment <PR番号> --body-file report.md
   ```

各指摘行には `finding-merge.md` の行文法どおり `file:line` と重大度が入っているため、コメント上でそのまま対応対象を特定できる。

## 指摘への対応記録

投稿した指摘には、**1 件ずつ「対応したかどうか」と「その理由」を残す**。指摘を読んだだけで流すと、同じ指摘が次のレビューで再発し、対応しなかった判断の理由も失われる。

記録はレポートコメントへの **返信 1 本** にまとめる (指摘ごとに返信を分けない):

```markdown
## 指摘への対応記録 (<timestamp>)

- [high] src/foo.ts:42 — 対応した (<commit hash / PR 内の修正箇所>)
- [medium] src/bar.ts:10 — 対応しない。理由: <設計上の意図 / 誤検知の根拠>
- [low] docs/baz.md#設計 — 後続対応。<issue 番号 / spec の未確定事項に記録した旨>
```

記録の規則:

- 対応の種別は 3 つだけ使う: `対応した` / `対応しない` / `後続対応`。
- `対応しない` には理由を必ず書く。「軽微なため」だけで終えず、判断の根拠 (誤検知 / 仕様どおり / スコープ外) まで書く。
- **`high` の指摘を `対応しない` にする判断はユーザーに確認する** (skill が独断で却下しない)。
- `後続対応` は行き先 (issue 番号 / spec の `## 未確定事項`) を明記する。行き先のない `後続対応` は使わない。
- 全指摘に記録が付いたら、レビューは消化済みとして扱ってよい。
