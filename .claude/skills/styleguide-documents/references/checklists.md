# チェックリストと仕上げ

文書を作成・更新したあとに通す点検リストと、最終的に到達すべき状態。

## 目次

- 適用チェック
- 推敲時の点検リスト
- 仕上げの原則

## 適用チェック

docs を作成または更新したら、次を確認する。

- [ ] 各記述の主語、対象、条件が一意に定まる。
- [ ] 主要な判断に理由がある。
- [ ] 採用しなかった選択肢が、必要な範囲で記録されている。
- [ ] 入力、出力、境界、受け入れ基準が、後続作業できる具体度になっている。
- [ ] 未確定点が未決事項として明示されている。
- [ ] 未決事項に、選択肢、影響、確認方法、担当、期限がある。
- [ ] 文書の粒度が、読者、目的、独立トピックの単位で分割されている。
- [ ] 上位文書と下位文書で、同じ情報を重複させていない。
- [ ] Why、What、How の所在が文書間で重複または矛盾していない。
- [ ] 図表が、文書の抽象度に合っている。
- [ ] 未確定事項を、確定事項のように図示していない。
- [ ] 正本が別にある情報を複製していない。
- [ ] 「適切に」「必要に応じて」「TBD」で逃げていない。
- [ ] レビューで何を判断すればよいかが明確である。

## 推敲時の点検リスト

文書を書き終えたら、次を確認する。

- この文書の目的が冒頭で分かるか。
- 読み手に求める行動が分かるか。
- 対象範囲と非対象が分かれているか。
- 事実、判断、仮定、未確認事項、未決事項が分かれているか。
- 要求と実現方法が混ざっていないか。
- 判断に理由と影響があるか。
- 制約が後続の判断で回収されているか。
- 未確認事項に確認方法、担当、期限、影響があるか。
- 未決事項に選択肢、担当、期限、影響があるか。
- 異常系、境界値、部分失敗が抜けていないか。
- 影響範囲が確認されているか。
- 用語が一貫しているか。
- 表や図が読み手の負荷を下げているか。
- 文書分割の粒度が適切か。
- 正本への参照と、この文書に書く内容の境界が明確か。
- レビューで何を判断すればよいかが明確か。
- 将来の保守者が、なぜその判断になったのかを追えるか。
- 言い換えだけの段落や、評価だけの文が残っていないか。

## 仕上げの原則

最後に、文書を次の状態まで整える。

- 読み手が最初の 1 分で、目的、対象範囲、求められる行動を理解できる。
- 実装者が、要求と実現方法を誤読しない。
- レビュアーが、判断すべき論点にコメントできる。
- 運用者が、失敗時に確認すべき状態を追える。
- 将来の保守者が、判断の背景と制約を追える。
- 未決事項が、後から追跡できる。
- 文書間の責務が分かれ、同じ情報を重複して持っていない。

docs は、読後感ではなく再利用性で評価する。
読んで納得できるだけでなく、判断、実装、レビュー、運用、保守で使える状態にする。
